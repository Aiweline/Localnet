# Localnet 局域网聊天工具设计规格

日期：2026-08-23

状态：待用户复核

目标平台：Windows、macOS

## 1. 产品目标

Localnet 是一个无需账号、无需中心服务器的局域网桌面通信工具。运行同一软件的设备在同一可进行 mDNS 组播的局域网内自动发现彼此。用户首次设置昵称，向附近用户发送好友申请；对方接受后，双方可以直接发送文字、图片和文件。

首版成功标准：

1. 两台位于同一局域网的 Windows/macOS 设备启动软件后，通常在 10 秒内互相出现在“附近用户”列表。
2. 用户可以发送好友申请；只有对方接受后，双方才进入好友列表并能聊天。
3. 好友在线时可以点对点发送文字、图片和文件，并看到清晰的发送、传输、成功或失败状态。
4. 身份、好友、聊天记录和接收内容只保存在本机；软件不连接业务服务器或云端服务。
5. 应用重新启动后保留身份、好友与聊天记录。

## 2. 首版范围

包含：

- 首次启动设置昵称。
- 自动生成并持久化设备身份。
- 局域网在线用户自动发现和离线检测。
- 好友申请、接受、拒绝。
- 好友列表和在线状态。
- 一对一文字聊天。
- 图片发送、接收与聊天内预览。
- 文件发送、接收、保存位置选择、进度、取消和失败重试。
- 本地聊天记录与传输记录。
- Windows 与 macOS 安装产物。

不包含：

- 登录注册、手机号或邮箱账号。
- 中心服务器、云同步、互联网通信或跨子网中继。
- 离线消息投递。
- 群聊、语音、视频、表情商店、撤回、已读回执。
- 手机端和 Linux 端。
- 自动升级与组织管理后台。

## 3. 技术方案

### 3.1 桌面应用

- Tauri 2：桌面窗口、系统能力、权限、安装包。
- React + TypeScript：GUI 与交互状态。
- Rust：网络、身份、协议、数据库和文件传输。
- SQLite：本地设置、联系人、申请、消息和传输记录。
- rust-libp2p：mDNS 发现、点对点连接、身份认证和多路复用。

前端不直接访问网络或任意文件。React 只通过有限的 Tauri command 调用 Rust，并通过 Tauri event 接收在线状态、消息与传输进度。

### 3.2 点对点网络

每个客户端持有一对长期 Ed25519 身份密钥，公钥派生的 Peer ID 是稳定身份。昵称是可修改的显示信息，不作为身份主键。

网络层使用：

- mDNS：发现同一局域网内的 Localnet 节点及其监听地址。
- TCP：可靠传输。
- Noise：连接加密与对端身份认证。
- Yamux：在一条连接上承载控制消息、聊天消息与文件流。
- request-response 协议：好友申请、接受/拒绝、文字消息和文件元数据。
- 独立流协议：分块传输图片和文件，避免把大文件加载进内存。

mDNS 发现结果只代表“附近存在一个节点”；在加密连接完成并校验 Peer ID 前，不将其视为可信好友。

## 4. 组件边界

```text
React GUI
  ├─ 首次设置页
  ├─ 左侧用户/好友/申请列表
  ├─ 会话页
  └─ 图片与文件传输卡片
          ↕ Tauri commands / events
Rust Application Core
  ├─ IdentityService     身份密钥和昵称
  ├─ DiscoveryService    mDNS 发现与在线状态
  ├─ FriendService       好友申请与关系状态
  ├─ MessageService      文字和图片消息编排
  ├─ TransferService     文件元数据、分块、校验和进度
  ├─ StorageRepository   SQLite 和本地文件目录
  └─ NetworkRuntime      libp2p Swarm 与协议路由
```

各服务通过明确的数据结构通信；GUI 不依赖 libp2p 或数据库实现细节，网络协议也不依赖具体界面组件。

## 5. 用户界面

### 5.1 首次启动

展示产品名称和一个必填昵称输入框。昵称去除首尾空格，长度限制为 1 至 32 个 Unicode 字符。点击“开始使用”后生成身份并进入主窗口。

### 5.2 主窗口

主窗口采用左右两栏：

- 左侧固定宽度约 300px。
  - 顶部：本人昵称、在线状态和设置入口。
  - “好友申请”：显示待处理数量，进入后可接受或拒绝。
  - “好友”：已添加用户，显示在线/离线状态和未读数。
  - “附近用户”：自动扫描到、尚未成为好友的用户，显示昵称、Windows/macOS 标记和“添加好友”按钮。
- 右侧自适应。
  - 未选择用户：显示简洁空状态和操作提示。
  - 好友申请：显示申请人和接受/拒绝操作。
  - 聊天状态：顶部显示好友昵称和在线状态，中部显示消息流，底部显示文字输入框、图片按钮、文件按钮和发送按钮。

文字消息区分发送中、已送达和失败。图片在聊天内显示缩略图，点击后查看原图。文件显示文件名、大小、进度、取消、失败重试和完成后打开所在位置。

### 5.3 交互原则

- 不使用阻塞式系统弹窗处理普通状态；申请、错误和结果在页面内或非阻塞通知中展示。
- 好友离线时禁用发送并解释原因，不制造“已经发出”的假象。
- 文件接收前由接收方选择保存位置；图片由好友发送时保存到应用数据目录并在聊天中显示。
- 键盘 Enter 发送，Shift+Enter 换行；按钮具有键盘焦点和无障碍名称。
- 界面支持浅色与深色系统主题，窗口缩小时保持聊天区可用。

## 6. 核心流程

### 6.1 启动与发现

1. 加载或创建身份与本地数据库。
2. 启动 libp2p 监听和 mDNS 服务。
3. 收到发现事件后建立加密连接，获取对方 Peer ID、昵称、平台和协议版本。
4. GUI 更新“附近用户”或好友在线状态。
5. 一段时间未发现且连接已关闭时，用户状态变为离线，而不是从好友记录中删除。

### 6.2 添加好友

1. 发起方点击“添加好友”。
2. FriendService 发送带唯一请求 ID 的申请，并把本地状态记为“等待接受”。
3. 接收方看到申请，选择接受或拒绝。
4. 接受时双方按 Peer ID 写入好友记录；拒绝时发起方看到明确结果。
5. 重复申请按请求 ID 幂等处理，不生成多个关系或多条申请。

### 6.3 文字消息

1. GUI 创建本地消息并显示“发送中”。
2. MessageService 校验双方是好友且当前连接可用。
3. 发送包含消息 ID、发送方 Peer ID、本地时间和 UTF-8 正文的协议消息。
4. 对方落库成功后返回确认，发送方标记“已送达”。
5. 超时或连接断开时标记“失败”，允许用户手动重试；首版不在对方离线时排队投递。

### 6.4 图片与文件

1. 发送方选择本地内容，软件读取元数据并计算 SHA-256。
2. 先发送传输邀请：传输 ID、类型、文件名、大小、MIME 类型和哈希。
3. 普通文件由接收方选择保存位置并确认；来自好友且不超过 25 MB 的图片可以直接接收至应用图片目录。
4. 接收方确认后，发送方通过独立流按块读取和写入，双方持续更新进度。
5. 接收内容先写入 `.part` 临时文件，完成后校验大小与 SHA-256；校验通过再原子改名。
6. 取消、断开或校验失败时保留失败记录并清理不完整文件；手动重试会重新开始传输。

首版限制单个文件最大 2 GB、单条文字最大 16 KiB。限制在发送方和接收方同时校验。

## 7. 本地数据

SQLite 至少包含以下逻辑表：

- `settings`：昵称、外观等非敏感设置。
- `identity`：Peer ID 和加密保存的私钥材料引用。
- `peers`：发现过的节点、最后昵称、平台、最后在线时间。
- `friend_requests`：请求 ID、方向、状态和时间。
- `friends`：好友 Peer ID、添加时间和本地备注预留字段。
- `messages`：消息 ID、好友、方向、类型、正文/本地内容引用、状态和时间。
- `transfers`：传输 ID、文件元数据、本地路径、进度和状态。

私钥优先写入操作系统凭据存储；如果平台能力不可用，则使用仅当前用户可读的应用数据文件，并在界面中提示安全级别。收到的文件路径必须经规范化，不能由远端文件名控制目录，以阻止路径穿越和覆盖现有文件。

## 8. 安全与隐私

- 所有聊天与传输连接均加密，并使用稳定 Peer ID 验证对端。
- 未成为好友的节点只能交换发现信息和好友申请，不能发送聊天或文件。
- 对陌生节点的申请频率和并发连接数进行限制。
- 不加载远程网页、远程脚本或第三方 CDN；启用严格的 Tauri CSP 和最小权限。
- 文件名仅作显示建议，保存路径由接收方本机决定。
- 不采集遥测，不上传通讯录、聊天记录或文件。
- 删除好友后立即阻止新的聊天和传输；历史记录默认保留，由用户单独清理。

## 9. 异常与系统权限

- 防火墙或 macOS 本地网络权限被拒绝：显示“无法发现局域网用户”，提供系统设置指引和重新检测按钮。
- 企业 Wi-Fi 开启客户端隔离、禁用组播或设备不在同一子网：明确说明自动发现不可用，首版不提供手工 IP 连接作为隐藏降级路径。
- 网络切换、睡眠唤醒：重启发现过程并重建在线状态，不删除好友关系。
- 协议版本不兼容：附近列表显示“版本不兼容”，不尝试发送数据。
- 磁盘空间不足或无写入权限：传输立即失败，保留可理解的原因，不留下伪完成记录。
- 应用崩溃恢复：数据库使用事务；未完成传输在下次启动时标记失败并清理残留临时文件。

## 10. 打包与兼容范围

- Windows：Windows 10/11 x64，提供安装程序。
- macOS：macOS 12 及以上，提供 Apple Silicon 和 Intel 构建或通用应用包。
- Windows 和 macOS 分别在对应操作系统上构建；macOS 正式分发需要签名和公证，Windows 正式分发建议代码签名。
- 开发期先交付可本地安装的测试包，签名证书不属于首版代码范围。

## 11. 验收方案

使用两台真实设备或两套隔离进程完成端到端验证：

1. Windows ↔ Windows 自动发现、申请、接受、文字、图片和文件。
2. macOS ↔ macOS 同流程。
3. Windows ↔ macOS 同流程。
4. 拒绝好友申请后不能发消息；重复申请不产生重复好友。
5. 好友离线、传输中断、取消、哈希失败和磁盘写入失败均显示真实状态。
6. 重启应用后身份、好友和聊天记录仍在，在线状态能够恢复。
7. 验证大文件以流方式传输，进程内存不会随文件大小线性增长。
8. 验证防火墙/本地网络权限提示、浅色/深色主题和窄窗口布局。

除构建和静态检查外，首版的完成门槛是 Windows 与 macOS 真实应用之间的局域网冒烟成功；无法实际验证的平台必须明确标记为未验证。

## 12. 实施顺序

1. 工程骨架、身份与本地存储。
2. 单实例启动和 mDNS 自动发现。
3. 好友申请状态机。
4. 一对一文字消息。
5. 图片与文件流式传输。
6. 完整 GUI、错误状态和系统权限指引。
7. Windows/macOS 打包与跨平台真实验收。
