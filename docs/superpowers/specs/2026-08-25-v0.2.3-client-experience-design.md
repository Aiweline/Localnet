# Weline Localnet v0.2.3 Client Experience Design

## 目标

Weline Localnet v0.2.3 同时解决四个用户结果：Windows 安装时可从 10 种语言中主动选择；已经建立的好友只出现在好友列表且不再出现添加按钮；首次启动默认申请系统通知权限；界面显示当前版本并能从 GitHub Release 检测、下载和打开更新包。

## 已确认事实与根因

- 当前 NSIS 配置已经声明 English、SimpChinese、Spanish、French、German、PortugueseBR、Russian、Japanese、Korean、Arabic，但 `displayLanguageSelector` 未开启，因此安装器直接采用系统语言而不显示选择窗口。
- 当前应用只读取系统通知权限，不会在首次启动时主动申请，所以默认状态仍可能是未开启。
- 截图中的“双方已经是好友，无需重复申请”来自旧版客户端。公开的 v0.2.2 源码已经移除该错误分支，并将重复添加改为幂等成功；界面仍没有版本号，因此用户无法确认实际运行的版本。
- 当前发布流程在 GitHub Release 提供 Windows x64 安装版、Windows x64 便携版、macOS Universal DMG 和 SHA-256 信息，但应用没有消费这些发布信息。

## 产品行为

### 1. Windows 安装语言

Windows NSIS 安装器在主安装界面出现前显示语言选择窗口，提供以下 10 种语言：

1. English
2. 简体中文
3. Español
4. Français
5. Deutsch
6. Português (Brasil)
7. Русский
8. 日本語
9. 한국어
10. العربية

用户选择只影响 NSIS 安装和卸载界面。macOS 继续发布 Universal DMG；DMG 没有安装向导，因此不伪造不存在的语言选择步骤。

### 2. 好友状态收敛

好友关系以本地 SQLite `friends` 表和经过身份认证的对端好友确认消息为权威来源。界面必须满足：

- `friends` 中存在的 peer 永不出现在附近用户列表。
- 接受好友申请后，事件到达时立即把 peer 移入好友列表；后台快照继续兜底。
- 对旧版残留界面再次点击添加时，新版命令把现有好友视为幂等成功，不要求对端在线，也不发送重复申请。
- 当一端已有好友、另一端仍是旧的非好友状态时，新版收到已认证对端的好友确认后补齐本地好友记录；不能只隐藏按钮而不修复好友列表。
- 标题旁显示版本号，使截图可以直接判断是否仍在运行旧版本。

不通过昵称、IP 或 MAC 地址推断好友身份；好友键仍是 libp2p PeerId，避免同名和地址变化造成误认。

### 3. 系统通知默认申请

应用首次启动时检查系统权限：

- 已授权：直接标记为已开启。
- 尚未决定：自动调用系统授权请求一次。
- 已拒绝：尊重系统选择，不在以后每次启动重复弹出权限窗口。
- 权限 API 失败：应用继续运行，保留应用内好友申请提醒，并在设置中允许用户重试。

“默认开启”表示应用主动申请并在系统允许后启用，不代表绕过 Windows 或 macOS 的权限确认。

### 4. 版本展示与 GitHub 更新

侧边栏标题显示 `Weline Localnet vX.Y.Z`。版本从 Tauri 应用元数据读取，不维护第二份前端常量。

应用启动后异步查询：

`https://api.github.com/repos/Aiweline/Localnet/releases/latest`

更新检查不阻塞内网发现、聊天或文件传输。比较规则为稳定 SemVer：只有远端 `vMAJOR.MINOR.PATCH` 严格高于本地版本时才提示更新；草稿、预发布、非法版本和降级版本全部忽略或作为安全错误处理。

界面在标题区域或设置中显示以下状态：

- 已是最新版
- 检查失败，可重试
- 发现 `vX.Y.Z`，可下载
- 正在下载及进度
- 校验失败
- 下载完成，打开安装包

### 5. 更新下载与打开

更新逻辑按平台选择精确资产：

- Windows：`Weline_Localnet_<version>_x64-setup.exe`
- macOS：`Weline_Localnet_<version>_universal.dmg`

应用只接受以下发布来源：

- GitHub 仓库必须是 `Aiweline/Localnet`。
- 下载 URL 必须为 HTTPS，并与该仓库、精确 tag 和精确资产名匹配。
- GitHub Release 的资产状态必须为 `uploaded`。
- 资产必须包含 `sha256:<64 hex>` digest。

后端 Rust 命令把文件流式下载到应用缓存目录中的临时文件，下载完成后计算 SHA-256。只有摘要与 GitHub Release digest 完全一致时，才原子改名为最终更新包并允许打开。失败或中断时删除本次未完成临时文件，不触碰用户文件。

校验通过后：

- Windows 打开安装程序；系统仍可显示 UAC、SmartScreen 或安装确认。
- macOS 打开 DMG；用户按标准方式拖入 Applications。
- 应用不静默安装、不绕过系统安全提示、不自动删除当前版本数据。

## 组件边界

### 前端 `src/update.ts`

负责稳定 SemVer 解析、GitHub Release 响应校验、平台资产选择和可测试的更新状态模型。网络请求与下载命令通过依赖注入边界调用，单元测试不访问真实 GitHub。

### 前端 `src/main.tsx`

负责启动时读取应用版本、触发一次更新检查、展示标题版本和更新状态、处理用户点击下载/重试/打开。好友列表继续使用权威快照和即时事件合并。

### 后端 `src-tauri/src/update.rs`

负责下载、大小上限、临时路径、SHA-256 校验、原子完成和打开前的本地文件校验。它不决定是否有新版本，也不接受任意 URL 或任意目标路径。

### Tauri 配置与权限

`tauri.conf.json` 开启 NSIS 语言选择器并允许前端访问 GitHub API。Tauri capability 只增加更新命令实际需要的最小权限，不授予任意文件系统写入或任意 shell 执行能力。

### GitHub 发布工作流

现有五资产不可变发布模型保持不变。发布门禁继续验证精确资产名和 SHA-256；应用使用 GitHub API 已提供的资产 digest，不新增自建更新服务器。

## 错误处理

- GitHub 不可达、代理不可用或限流：显示“检查更新失败”，不影响内网功能。
- Release JSON 不完整或来源不可信：拒绝更新并显示安全错误，不猜测资产。
- 下载断开：本次更新回到可重试状态，临时文件不被当成有效安装包。
- SHA-256 不匹配：删除临时文件，拒绝打开。
- 打开安装包失败：保留已校验安装包并提供重试，不重新下载。
- 通知被拒绝：应用内通知仍可用，设置页显示需要到系统设置重新授权。

## 测试与验收

### 自动化

- NSIS 配置通过 Tauri schema，并在 Windows CI 构建日志/产物验证中确认 10 种语言和选择器启用。
- 前端测试覆盖 SemVer 高低比较、非法 tag、预发布忽略、错误仓库/URL/资产名、Windows/macOS 精确资产选择。
- 后端测试覆盖成功下载、超限、断流、错误摘要、临时文件清理、目标缓存目录边界。
- 好友回归覆盖：现有好友、accepted request 和即时 resolved event 都不能再出现在附近用户中；离线旧状态点击不派发重复请求。
- 通知状态测试覆盖 granted/default/denied/error 四条路径，default 只申请一次。

### 发布验收

- 本地 TypeScript、Node、Rust、Tauri schema、Vite 和格式检查全部通过。
- Windows CI 构建 NSIS 安装器并验证版本、语言选择配置和安装包资产。
- macOS CI 构建并验证 Universal DMG、双架构和版本。
- GitHub Release 为公开、非草稿、非预发布、immutable，tag 与 main 精确一致，五个资产全部为 uploaded。
- 不在开发机启动 GUI，避免再次触发大量系统授权窗口；通知和安装器视觉行为由平台 CI 产物与配置门禁验证。

## 版本与兼容性

- 发布版本为 `0.2.3`。
- 不修改 PeerId、局域网发现协议、好友表主键或文件传输协议。
- 0.1.x 和 0.2.x 继续能够发现并发送好友申请；新版客户端负责显示自身版本并引导升级。
- 更新检查依赖互联网，但互联网不可用时所有内网通信能力保持可用。
